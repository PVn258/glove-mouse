# 手套鼠标（Glove Mouse）项目报告

> **项目版本**：v1.0  
> **日期**：2026-05-06  
> **平台**：ESP32-C6 + NimBLE + MPU-6050 + FSR402 + 弯曲传感器

---

## 执行摘要

本项目设计并实现了一款基于手套形态的无线可穿戴鼠标。用户将装有传感器的手套戴在手上，通过弯曲拇指切换传输/休眠模式，手腕姿态控制鼠标光标，食指和小指区的压力传感器模拟鼠标左右键。系统核心为 ESP32-C6-MINI-1 模组，通过 BLE HID 协议与主机通信，无需任何驱动程序，可在 Windows / macOS / Linux / Android 上即插即用。配套设计了完整的硬件 PCB，包含锂电池充放电保护链路、ESD 防护和模拟信号调理电路。

## 一、项目介绍

### 1.1 产品定位

手套鼠标是一种**可穿戴式人机输入设备**，其核心价值在于将鼠标的控制权从桌面平面解放至三维空间中的手腕姿态，适用于：

- 站立式演示与讲演（PPT 翻页 + 鼠标操作）
- 移动场景下的计算机控制（不依赖平面支撑）
- 无障碍辅助（行动不便用户的替代输入方案）
- AR/VR 混合场景中的辅助指点设备

### 1.2 核心功能

| 功能 | 实现方式 |
|------|----------|
| 光标移动 | MPU-6050 陀螺仪（手腕姿态 → dX/dY） |
| 左键点击 | 食指区 FSR402 压力传感器 → LM339 比较器 → GPIO23 |
| 右键点击 | 小指区 FSR402 压力传感器 → LM339 比较器 → GPIO16 |
| 模式切换 | 拇指弯曲传感器 → LM339 比较器 → GPIO17（弯曲=传输，伸直=休眠） |
| 无线通信 | BLE 5.0 HID Mouse Profile（NimBLE 协议栈） |
| 电源管理 | TP4056 充电 + DW01A/FS8205A 电池保护 + ME6211C33 3.3V LDO |

### 1.3 技术规格

| 指标 | 数值 |
|------|------|
| 主控芯片 | ESP32-C6-MINI-1（RISC-V 160MHz） |
| BLE 版本 | BLE 5.0 |
| 报告率 | ~62.5 Hz（16ms 周期） |
| BLE 连接间隔 | 20–30 ms（Windows 兼容） |
| 光标死区 | ±3 °/s |
| 最大角速度量程 | ±80 °/s（→ 对应最大像素 32/18） |
| 电池容量（参考） | 1000 mAh 锂聚合物（最大电流 ~200 mA，续航 > 5h） |
| PCB 制造工艺 | 嘉立创 SMT 贴片（LCSC 元件编号，BOM 齐全） |

## 二、背景

### 2.1 传统鼠标的局限

自 Douglas Engelbart 于 1964 年发明鼠标以来，鼠标的基本形态历经六十年几乎未发生根本性变革。传统鼠标的固有局限包括：

- **依赖平面**：需要平整桌面或鼠标垫，限制了使用场景；
- **线缆束缚**（有线鼠标）或**有限无线范围**：不适合自由行走的演示场景；
- **单手占用**：无法同时进行书写、举物等操作；
- **不适用于特殊人群**：上肢运动能力受限者难以精确操控传统鼠标。

### 2.2 可穿戴计算的兴起

Mark Weiser（1991）在论文《21 世纪的计算机》中提出"平静技术（Calm Technology）"愿景：技术应退隐于人类行为之中，成为自然延伸而非显性工具。这一理念直接推动了可穿戴计算设备的研究热潮：从早期的 MIT Media Lab Wearable Computing Group，到现代的 Apple Watch、Meta Ray-Ban 智能眼镜，技术正逐步从桌面迁移至人体。

在输入设备领域，这一趋势表现为从"使用工具"向"成为工具"的转变——用户的肢体动作本身成为输入信号。

### 2.3 手势识别技术演进

手势输入的技术路线经历了三个阶段：

1. **摄像头 + 计算机视觉**（如 Leap Motion）：精度高，但需固定摄像头、受光照干扰、计算功耗高；
2. **EMG 肌电信号**（如 Myo Armband）：可识别丰富手势，但传感器贴合度要求高、需个性化训练；
3. **惯性传感（IMU）**：基于 MEMS 陀螺仪和加速度计，功耗极低、延迟小、成本低，适合穿戴式连续使用。

本项目选择第三条路线，以 MPU-6050 六轴 IMU 为核心，辅以 FSR 压力传感器处理离散点击事件，兼顾成本、功耗和实时性。

### 2.4 BLE HID 协议的成熟

蓝牙 HID（Human Interface Device）协议最早在蓝牙经典（BR/EDR）上定义，BLE 4.0 引入后 HID over GATT Profile（HOGP）成为标准。现代操作系统（Windows 10+、macOS 10.15+、Android 8.0+、Linux BlueZ 5.x）已内置对 BLE HID 鼠标的原生支持，无需第三方驱动程序，实现真正的即插即用体验。

## 三、交互范式

### 3.1 具身交互（Embodied Interaction）

Paul Dourish 在《Where the Action Is: The Foundations of Embodied Interaction》（2001）中指出，传统 GUI 将计算机操作抽象为符号层面的交互（点击图标、拖动窗口），而具身交互则主张将计算系统嵌入物理世界和身体动作之中。

本项目的手势控制范式正是具身交互的实践：

- 手腕的**旋转**直接映射为光标的水平移动；
- 手腕的**俯仰**直接映射为光标的垂直移动；
- **拇指弯曲**的自然动作成为系统意图的表达，而非按下某个"模式键"。

用户无需理解"我在操作一台计算机"，而是"我在用手势移动屏幕上的东西"，认知成本大幅降低。

### 3.2 直接操纵（Direct Manipulation）

Ben Shneiderman（1983）提出直接操纵的三个原则：

1. **持续呈现操作对象**（屏幕光标始终可见）；
2. **物理动作替代复杂语法**（手腕动作替代鼠标拖动）；
3. **操作可快速、可逆、可增量**（停止手腕运动即停止光标）。

本项目完整满足这三项原则，光标移动与手腕姿态之间的映射是实时、连续、可逆的。

### 3.3 自然用户界面（NUI）

NUI（Natural User Interface）强调利用用户已有的身体动作语言，减少专项学习成本。与传统鼠标相比，手套鼠标的学习曲线更接近"手指指向"的直觉动作，而非"移动外部工具"的工具使用模式。

### 3.4 模态交互（Modal Interaction）

系统采用**二态模态设计**：

- **传输模式**（拇指弯曲）：IMU 数据激活，实时发送鼠标报文；
- **休眠模式**（拇指伸直）：IMU 数据冻结，不发送任何移动指令（仍响应按键）。

这一模态门控设计解决了"持续佩戴"与"意图输入"之间的冲突——用户手臂自然下垂时不会产生误触，弯曲拇指这一明确意图动作才激活光标控制。

## 五、设计方案

### 5.1 系统架构总览

```

│                    手套鼠标系统架构                       │
├─────────────────┬───────────────────────────────────────┤

│                 │                    │                   │

│                 │ 幂律曲线映射        │ (NimBLE, 62.5Hz)  │
```

### 5.2 硬件架构

#### 5.2.1 主控模组

**ESP32-C6-MINI-1**（LCSC C5783079）：

- 处理器：单核 RISC-V 160 MHz
- 无线：Wi-Fi 6（802.11ax）+ BLE 5.0（IEEE 802.15.4 Thread/Zigbee）
- 集成天线，模组尺寸 13.2 × 16.6 mm
- 支持 NimBLE 协议栈，原生 HID over GATT

引脚分配：

```
GPIO0  → MPU-6050 SDA（I2C）
GPIO1  → MPU-6050 SCL（I2C）
GPIO16 → FSR 右键 DO（INPUT_PULLUP，LOW=按压）
GPIO17 → 弯曲传感器 DO（INPUT_PULLUP，LOW=弯曲）
GPIO23 → FSR 左键 DO（INPUT_PULLUP，LOW=按压）
```

#### 5.2.2 惯性测量单元

**MPU-6050**（LCSC C24112，I2C 地址 0x68，AD0→GND）：

- 量程：±250 °/s（默认，LSB = 131 counts/°s）
- 采样率：I2C 400 kHz，固件以 62.5 Hz 读取
- 供电：3.3V 模拟电源（经铁氧体磁珠 BLM15AG601SN1D 与数字 3.3V 隔离）

#### 5.2.3 模拟信号调理

弯曲传感器和两路 FSR402 压力传感器均输出模拟阻值变化，使用 **LM339 四路比较器**（LCSC C7701）将其转换为数字 DO 信号：

- 每路比较器正端接传感器电阻分压，负端接可调电位器 **3224W 10kΩ 微调电位器**（LCSC C128917）；
- 比较器输出为开漏（Open-Drain），ESP32 侧配置 `INPUT_PULLUP` 避免浮空；
- 用户可通过调节电位器设定触发灵敏度阈值，无需修改固件。

#### 5.2.4 电源链路

```
USB-C (5V) ──[ESD: USBLC6-2SC6]──[PTC Fuse 500mA]──> TP4056
                                                         │ 充电
                                                     锂电池 (3.7V)
                                                         │ 放电
                                                     DW01A + FS8205A
                                                  （过充/过放/短路保护）
                                                         │
                                                   ME6211C33 (3.3V LDO)
                                                         │
                                          ┌──────────────┼──────────────┐
                                      3V3_DIG        [FB: 铁氧体]   ESP32-C6
                                   (数字域)           BLM15AG601     (GPIO)
                                                         │
                                                     3V3_ANALOG
                                                     (MPU-6050)
```

- **TP4056**（LCSC C16581）：CV/CC 锂电池充电 IC，充电电流由 R_prog（2kΩ）设定为 ~500mA；
- **DW01A + FS8205A**（LCSC C351073 / C32254）：标准锂电池保护组合，防过充（>4.28V）、过放（<2.5V）、短路；
- **ME6211C33M5G**（LCSC C82942）：200mA LDO，输出稳定 3.3V，低压差 0.1V；
- **铁氧体磁珠 BLM15AG601SN1D**（LCSC C76563）：在 100MHz 处阻抗 600Ω，隔离数字开关噪声对 MPU-6050 模拟电源的影响。

### 5.3 固件算法

固件路径：`D:\glove mouse\glove_mouse\glove_mouse.ino`

#### 5.3.1 主循环结构（16ms 周期）

```
loop():
  ├─ 读取传感器原始值（digitalRead × 3）
  ├─ 弯曲传感器防抖（40ms 对称防抖）→ flex_active
  ├─ 左键防抖（非对称：按下 0ms，松开 25ms）→ deb_left
  ├─ 右键防抖（1ms 双向）→ deb_right
  ├─ 构建 buttons 字节（bit0=左，bit1=右）
  ├─ if (flex_active):
  │    ├─ if (gap > 80ms): 重置 EMA，跳过本帧
  │    ├─ MPU-6050 读取六轴原始值
  │    ├─ 轴融合 → combined_x, gx_dps
  │    ├─ EMA 平滑（α=0.20）
  │    ├─ 幂律曲线映射 → mx, my
  │    └─ if (mx || my || btn_dirty): 发送 HID 报文
  └─ if (!flex_active):
       └─ if (btn_dirty): 发送零移动报文（释放按键）
```

#### 5.3.2 陀螺仪轴融合

MPU-6050 固定于手背，传统单轴映射会因手腕的复合运动产生串扰。通过实验发现，水平光标移动由**小臂旋转（GY）**和**手腕侧弯（GZ）**共同贡献，将两者相减可消除串扰：

```cpp
float combined_x = (gy - gz) / GYRO_LSB;   // 水平（左右）
float gx_dps     = gx / GYRO_LSB;           // 垂直（上下）
```

#### 5.3.3 EMA 低通滤波

指数移动平均（EMA）滤除手部高频抖动：

```cpp
ema_x = 0.20f * combined_x + 0.80f * ema_x;
ema_y = 0.20f * gx_dps     + 0.80f * ema_y;
```

α=0.20 对应约 1.6 Hz 截止频率（采样率 62.5 Hz），有效抑制手部颤抖（通常 8–12 Hz），同时保留意图性手腕动作的响应速度。

#### 5.3.4 幂律增益曲线

```cpp
float norm = (|ω| - DEADZONE) / (MAX_DPS - DEADZONE);
float output = pow(norm, 1.4) * MAX_MOVE;
```

指数 1.4 产生凹形（sub-linear）曲线：低速时增益被压缩（精确控制小目标），高速时增益趋近线性（快速跨屏移动）。相比线性映射，这种曲线更符合 Fitts' 定律对"精度-速度权衡"的量化预测。

#### 5.3.5 非对称左键防抖

FSR 压力传感器在压力持续施加时，机械弹振可能导致 DO 信号在 LOW 附近多次翻转：

```cpp
if (raw_left) {
    deb_left = true;           // 按下：立即确认（0ms 延迟）
    left_release_ts = 0;
} else if (deb_left) {
    if (left_release_ts == 0) left_release_ts = now;
    if (now - left_release_ts >= 25) deb_left = false;  // 松开：稳定 25ms
}
```

这种非对称设计保证按下响应无延迟（用户感受灵敏），同时防止松开时的弹振被错误识别为多次点击。

#### 5.3.6 btn_dirty 合并机制

若在光标移动过程中按键状态发生变化，天真地立即发送 `(buttons, 0, 0)` 会导致该帧光标移动中断，产生可见卡顿。`btn_dirty` 标志将按键状态变更合并到下一个包含有效移动量的帧中：

```cpp
if (buttons != last_sent_buttons) {
    last_sent_buttons = buttons;
    btn_dirty = true;
}
// 在有移动量时合并发送：
if (mx || my || btn_dirty) {
    sendMouseReport(last_sent_buttons, mx, my);
    btn_dirty = false;
}
```

### 5.4 BLE 实现

#### 5.4.1 协议栈选择

ESP32-C6 不支持传统 Bluedroid 栈（仅支持经典蓝牙 BR/EDR），原生运行 **NimBLE** 开源 BLE 栈。NimBLE-Arduino（h2zero，≥ 2.0）提供 C++ 封装，内置 `NimBLEHIDDevice` 类。

#### 5.4.2 HID 报文格式

```
Report ID = 1
Byte 0: 按键位掩码  [bit7..bit3=0 | bit2=中 | bit1=右 | bit0=左]
Byte 1: dX          int8_t, 范围 -127~127，正值=右移
Byte 2: dY          int8_t, 范围 -127~127，正值=下移
```

HID 报告描述符遵循 USB HID Usage Tables（Mouse, Generic Desktop Page）。

#### 5.4.3 Windows 兼容性处理

Windows 蓝牙 HID 驱动在连接建立后会周期性重协商连接参数（目标 7.5ms 极短间隔），导致协商期间约 500ms 的传输中断。解决方案：主动将连接间隔设定为 Windows 不会主动缩短的范围：

```cpp
server->updateConnParams(connInfo.getConnHandle(), 16, 24, 0, 300);
// 16×1.25=20ms min, 24×1.25=30ms max, latency=0, timeout=3s
```

#### 5.4.4 非阻塞发送

使用 `notify()` 而非 `indicate()`，发送失败（连接拥塞时）直接丢弃当前帧，不阻塞主循环，保持 62.5 Hz 的传感器读取稳定性：

```cpp
void sendMouseReport(uint8_t buttons, int8_t dx, int8_t dy) {
    if (!bleConnected || inputReport == nullptr) return;
    uint8_t report[3] = { buttons, (uint8_t)dx, (uint8_t)dy };
    inputReport->notify(report, sizeof(report));  // 非阻塞
}
```

### 5.5 PCB 设计

原理图通过 Python 脚本（`hardware/generate_schematic.py`）自动生成为 KiCad 6 `.kicad_sch` 格式，可直接导入立创 EDA 专业版。

**设计要点**：

- 所有 57 个元件均标注 LCSC 编号，支持嘉立创一键 SMT 拼单；
- MPU-6050 供电使用铁氧体磁珠与数字域隔离，减少 ESP32 GPIO 切换噪声对 IMU ADC 的干扰；
- USB-C 引脚 CC1/CC2 各接 5.1kΩ 下拉电阻，符合 USB-C 2.0 电源协议（标识设备为 UFP，触发充电器输出 5V）；
- LM339 比较器输出开漏，配合 ESP32 内部上拉使用，无需外部上拉电阻；
- JST PH2.0 接口分别预留电池、弯曲传感器、左键 FSR、右键 FSR 的连接。

## 六、人机交互设计理念

### 6.1 Fitts' 定律的量化应用

Fitts' 定律（1954）描述了运动时间 MT 与目标距离 D、目标宽度 W 之间的对数关系：

$$MT = a + b \cdot \log_2\left(\frac{2D}{W}\right)$$

高效的指点设备应在大目标（宽 W 大）时允许高速移动，在小目标（宽 W 小）时允许精细调整。本项目的幂律曲线（指数 1.4）正是对这一需求的工程实现：

- **低角速度区域**（接近死区）：输出增益被压缩，适合精确定位小按钮；
- **高角速度区域**（接近量程）：输出增益接近线性，适合快速跨越屏幕。

与传统鼠标的加速度曲线（操作系统层面的"指针加速"）相比，本项目将增益控制提前到硬件/固件层，具有更低的延迟和更可预测的行为。

### 6.2 模态设计的防错原则

拇指弯曲作为"意图门控"体现了工业设计中的**防错（Poka-Yoke）**原则：

- 系统默认处于**休眠（无输出）**状态，需要主动弯曲拇指才进入传输模式；
- 40ms 防抖确保偶然的手指弯曲（如自然姿势调整）不触发模式切换；
- 离开传输模式时自动发送全零报文，防止按键保持（stuck key）问题。

这与"安全默认（Safe Default）"的设计原则一致：系统失效时倾向于无害状态，而非产生意外输入。

### 6.3 具身认知与透明技术

Norman（1988）在《设计心理学》中提出"行为层次"模型：技术使用分为本能（Visceral）、行为（Behavioral）、反思（Reflective）三个层次。优秀的设计应将技术使用推至"行为层"，让用户无需主动思考（反思层）即可完成操作。

本项目通过手腕姿态到光标方向的直接、低延迟映射，使控制行为接近本能/行为层次：

- 用户无需记忆"按哪个键控制方向"；
- 手腕右倾即光标右移的映射符合空间直觉；
- 拇指弯曲类似"握住鼠标"的自然动作。

这与 Weiser 的"平静技术"愿景一致——技术在成功使用时应"消失"于用户感知之外。

### 6.4 渐进增益与容错性

**非对称防抖**体现了对人体生理特性的理解：

- 人手在主动按压时动作较为确定（较少误触），故按下 0ms 延迟最大化响应性；
- 人手在松开压力时存在机械弹振（FSR 的物理特性），故松开设置 25ms 稳定窗口防误报。

**EMA 滤波**作为"认知缓冲"容忍手部自然颤抖（尤其对于老年用户或手部稳定性较差的用户），无需用户刻意稳定手部。

### 6.5 人体工学与传感器布局

传感器的物理位置遵循**自然姿势优先**原则：

- **拇指**（模式传感器）：拇指弯曲是人手最自然、最低疲劳度的主动动作；
- **食指基节区**（左键）：食指按压动作力量最稳定，误触率最低；
- **小指或无名指区**（右键）：右键使用频率低，布局于弱侧手指降低误触；
- **手腕为主导轴**（光标）：手腕旋转/俯仰的运动范围大、肌肉群强，长时间使用不易疲劳。

BLE 无线连接消除线缆约束，允许用户在站立、行走或举臂（如演示场景）时自然保持设备使用，不会因线缆拉力而产生疲劳。

### 可扩展方向

1. **滚轮支持**：将 Z 轴加速度（俯仰高频分量）映射为滚轮位移；
2. **手势识别**：在 ESP32-C6 上运行轻量级分类器（如 DTW 或 1-NN），识别"弹指"、"握拳"等离散手势；
3. **漂移补偿**：引入互补滤波（陀螺仪积分 + 加速度计重力向量），补偿长时间使用的陀螺仪漂移；
4. **多手指 FSR**：扩展为 4 路 FSR（食指、中指、无名指、小指），实现更丰富的按键映射；
5. **屏幕显示**：添加微型 OLED，显示电池电量、连接状态、当前模式；
6. **自适应灵敏度**：根据用户使用习惯动态调整 EMA 系数和死区阈值。
